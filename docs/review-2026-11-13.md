## Entrega de la landing

- `web/index.html`: presentación Noctis autónoma, sin React, librerías JS/CSS ni
  build necesario para su propio documento. CSS y tres scripts inline. Vídeo y
  poster conservan las URL solicitadas; Google Fonts carga Plus Jakarta Sans.
- Se adapta la referencia a Noctis, en español, y se permite desplazamiento
  vertical para cumplir la petición de dashboard emergente. Por eso no se copia
  el `overflow:hidden` vertical ni el texto comercial de Sellix.
- Captura auténtica de la interfaz privada, **con fixtures sintéticas**, en
  base64 dentro de `web/index.html`. No representa datos productivos.
  Se reproduce con el servidor Vite activo y
  `cd web && node scripts/capture-dashboard.mjs`.
- `web/app.html` conserva el panel React; `/v2/login`, `/v2/*`, `/demo` y
  `/presentation` mantienen sus documentos/rutas tanto en Vite como en Go.
- La CSP autoriza los scripts de la landing mediante SHA-256 del HTML compilado;
  el panel privado conserva recursos locales y no recibe esas autorizaciones.
- El HTML incluye CSS, JS y captura; vídeo/poster y fuentes conservan sus
  dependencias remotas explícitas. No se incrustan decenas de MB de vídeo.

## Qué impide afirmar que está listo para funcionar

### 1. Telegram: reparar la recuperación antes de reanudar

El último estado **documentado**, no consultado hoy en el clúster, es captura
detenida con revisiones de fallo/reconocimiento 3/2. Una respuesta
`UpdatesChannelDifferenceTooLong` requiere intervención explícita; renovar el
consentimiento o reiniciar no arregla el cursor. Hay que identificar la fuente y
crear un procedimiento auditado de discontinuidad/baseline o exclusión.
Evidencia: `ops/rebuild/operations/telegram-startup-recovery.md:191–221`.

Además, la inspección señala dos regresiones por cubrir:

- `internal/telegramv2/rpc.go:304–324`: Difference confirma los marcadores de
  canal sin el `channelDifferenceByID` que sí usa Handle. Probar reconexión con
  aviso `UpdateChannelTooLong` y canal posteriormente silencioso.
- `internal/telegramv2/client.go:291` y `production.go:152`: sustituir sesión
  cambia generación y conserva el consentimiento anterior, cuya generación
  impide instalar sucesor. Diseñar transición auditada y probar renovación.

### 2. IA: existe integración, falta una ruta v2 acreditada

No falta instalar un modelo dentro del frontend: existen adaptadores Chat y
Responses compatibles con endpoints OpenAI. Faltan credencial cifrada con master
key disponible para API/worker, URL/modelo concretos, clases de datos autorizadas,
JSON estructurado, tarifas, presupuestos y límites por función. El estado inicial
tiene conexiones vacías y bindings deshabilitados (`internal/inference/config.go:31`).

**Bloqueo funcional:** `--automatic-inference=false`, predeterminado y usado en
el renderer de producción, impide tanto planificar como ejecutar `Store.Once`;
por ello también deja solicitudes manuales en cola
(`internal/runtimev2/runtime.go:222–237`). Separar consumo manual y planificación
automática exige una decisión explícita que conserve los límites de gasto.

«Validar sin inferencia» solo valida estructura, no modelo, credencial ni red.
El último recibo real conserva STOP, **0/14 funciones v2 completas**, timeout de
120 s y reservas inciertas. Los éxitos históricos v1 con `gpt-6.1-sol` no acreditan
las funciones/prompt v2. No repetir llamadas inciertas automáticamente ni asumir
presupuesto restante. Evidencia:
`ops/rebuild/operations/ai-real-provider-receipt.md`, último bloque de ejecución v2.

Orden necesario: diagnosticar el timeout con evidencia conservada; seleccionar y
validar endpoint/modelo mediante campaña autorizada y acotada; comprobar resultado,
citas, coste/usage y cancelación; recorrer las 14 funciones antes de anunciar
compatibilidad completa. La calidad humana G6 y utilidad G7 siguen pendientes;
no habilitar promoción automática basándose en pruebas sintéticas.

- El despliegue real tuvo actividad y restore documentados: no es correcto tratar
  todo como implementación inexistente. Sin embargo, el restore productivo de
  74 tablas excluye copia externa, actividad posterior y ruta pública. Hace falta
  restauración actual de esquema 007, claves, roles/DSN y servicio representativo,
  desde otro dominio de fallo. Los recibos anteriores de 68 tablas/006 tienen
  alcance histórico. Véanse `deploy/v2/production/README.md` (backup/recibos) y
  `ops/rebuild/operations/README.md:130–160`.
- Kubernetes omite timeout de probe aunque el handler concede 3 s; renderer y
  plantilla discrepan en recursos de worker. Un nodo, una API y `Recreate` implican
  indisponibilidad durante fallos/actualizaciones, no alta disponibilidad.
- CI tiene checks obligatorios Go sin skips, pero el runner navegador no acredita
  conteos/skips en su recibo. Hay módulos `tools/test_*.py` fuera de `make ci`.
  No se modificó CI ni se disparó ejecución remota; no se afirma ahorro medido.
- `npm audit --json` informó una vulnerabilidad moderada en Vite 6.4.4:
  [GHSA-8g5g-mxqh-grgj](https://github.com/vitejs/vite/security/advisories/GHSA-8g5g-mxqh-grgj),
  bypass de `server.fs.deny` mediante queries. El aviso oficial identifica 6.4.5
  como versión corregida; queda actualizar y verificar compatibilidad. No se
  aplicó `audit fix` automáticamente.
  Es una herramienta de desarrollo/build y el binario productivo sirve assets
  estáticos desde Go. Recibo: `/tmp/noctis-npm-audit-20261113.json`.
- STIX/TAXII, OCR, embeddings, SIEM y multiusuario son extensiones condicionadas,
  no requisitos necesarios para recuperar la captura mecánica conservadora.
